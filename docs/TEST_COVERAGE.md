# Workflow Test Coverage Map

The production test suite separates policy assertions from procedure-level contracts so that the system checks both pure decision logic and the boundaries where data is persisted or external work is requested.

| Coverage category | Primary test module | What is asserted |
|---|---|---|
| Authorization | `server/platform.integration.test.ts` | Active membership is required; editors can edit; clients can review but cannot edit. |
| AI task validation | `server/taskPolicy.test.ts` | Capability contracts, fallbacks, enabled-state, commercial-use, and capability matching rules. |
| Structured scripts | `server/scriptPolicy.test.ts` | Scene structure and approval-aware regeneration rules. |
| Job transitions | `server/platform.integration.test.ts` | Job updates persist and emit a matching job-event record. |
| Copilot tools | `server/copilot.integration.test.ts` | Only executable whitelisted tools are accepted; malformed outputs are rejected; publication plans require approval. |
| Asset rights | `server/assetRights.integration.test.ts` | Licensed assets are routed to manual review and unlicensed assets remain `unknown`; neither is silently marked verified. |
| Export worker safety | `server/exportPolicy.test.ts` | Missing workers are explicit and malformed worker responses are normalized safely. |
| Provider governance | `server/provider.integration.test.ts`, `server/providerPolicy.test.ts` | Free/self-hosted selection and paid-only rejection for all current modalities. |
| Public provider authorization and TTS | `server/provider.integration.test.ts`, `server/providerAdapter.test.ts`, `server/huggingFaceCredential.test.ts` | Production Script Studio verifies server-only router authorization; public TTS verifies server-side `InferenceClient` audio normalization, verified voice consent, tenant-scoped storage, and public-provider job completion. The configured token is separately validated against Hugging Face's official account endpoint. |
| Publishing workflow and approval boundary | `client/src/pages/Publishing.interaction.test.tsx`, `server/provider.integration.test.ts` | A platform-specific scheduled plan can be created without an official account, remains approval-required, supports governed platform adaptation and calendar/agenda rendering, and never implies direct posting success. The workspace explicitly defers official credential collection until the user elects to activate the selected platform(s); readiness returns only verified contract metadata, not credential values, and OAuth redirects remain fail-closed until a token-exchange adapter is available. |
| Social provider and dispatch safety | `server/socialProviderContracts.test.ts`, `server/socialPublishPolicy.test.ts`, `server/socialScheduling.test.ts`, `server/provider.integration.test.ts` | Official provider capability boundaries, inactive token-exchange adapters, missing credential names, LinkedIn manual-refresh limitation, account/approval/asset readiness, idempotency keys, queued-attempt creation, failed-attempt retry keys, error sanitization, six-field UTC callback cron conversion, and mocked schedule/reschedule/cancel Heartbeat lifecycle transitions are enforced without external calls. |
| Creator empty and guard states | `client/src/pages/creatorEmptyStates.test.tsx` | Script Studio, Research, Assets, Editor, Voice, Jobs, and Copilot render safe empty states; project-dependent creation controls remain disabled before project selection. |
| Creator mutation and query feedback | `client/src/pages/ScriptStudio.interaction.test.tsx`, `client/src/pages/Research.interaction.test.tsx`, `client/src/pages/AssetLibrary.interaction.test.tsx`, `client/src/pages/VoiceCaptions.interaction.test.tsx`, `client/src/pages/Copilot.interaction.test.tsx`, `client/src/pages/Jobs.interaction.test.tsx` | Project selection enables the action; successful mutations refresh or update review state and notify; rejected mutations preserve context and surface an actionable error. Voice coverage distinguishes public model-default synthesis from private-worker speed and delivery-direction controls. Every covered creator mutation disables repeat submission while pending. Query-loading states are explicitly rendered and tested for Research sources, Media Library assets, Voice catalog, Copilot action log, and Jobs refresh. |
| Timeline editing and export | `client/src/pages/TimelineEditor.interaction.test.tsx`, `client/src/pages/TimelineEditor.quickDraft.integration.test.tsx`, `client/src/components/QuickDraftExportButton.test.tsx`, `client/src/lib/draftVideoExport.test.ts` | Scene-property edits become dirty and persist through the editor procedure; save failures retain the draft; final MP4 submissions refresh export records and disable repeat submission while pending; the credential-free quick-draft path covers browser recording, real preview-component handoff, and download-anchor behavior. |
| Anonymous guest quick draft | `client/src/pages/GuestQuickDraft.test.tsx`, `client/src/App.guestRoute.test.tsx` | A public route creates and downloads a browser-local WebM with the real preview component, without a project, provider call, upload, persistence, or protected dashboard mount. Saved workspaces and provider-backed capabilities remain behind the authenticated route boundary. |

The suite intentionally uses controlled test doubles for storage, provider endpoints, the database, and the language model. It validates the application's decisions and persistence contracts without making external network calls or requiring credentials.
